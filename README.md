# Hexo Blog Platform

A full blogging platform on Railway: a fast static blog, a browser-based editor, comments, object storage and a web terminal — all behind **one public URL**.

[![Deploy to Railway](https://railway.app/button.svg)](https://railway.com/deploy/YOUR_TEMPLATE_CODE)

## Features

- **Hexo static site** — Markdown-powered blog (Hexo 8) served by nginx at `/`.
- **hexo-admin editor** — write, edit and publish posts from the browser at `/admin/`. Password-protected (auto-generated credentials on one-click deploy). New posts appear on the site within ~60 seconds (auto-regenerate loop).
- **Artalk comments** — self-hosted comment system at `/comment/` with SQLite storage on a persistent volume (PostgreSQL/MySQL optional via `ARTALK_DB_TYPE` + `DATABASE_URL`). Moderation dashboard at `/comment/sidebar/`.
- **MinIO S3 storage** — S3-compatible object storage at `/minio/` (path-style) with a web console at `/minio-console/`. Perfect for images, media, backups.
- **Web terminal** — ttyd shell at `/terminal/` for `hexo`, `git`, `mc`, `npm` and any maintenance task.
- **Persistent volumes** — `source/_posts` (your content), `public/` (generated site) and comment/S3 data survive restarts and redeploys.
- **Client-side search** — `/search.xml` generated by hexo-generator-searchdb.

## Quick Start

1. Click **Deploy to Railway** (button above).
2. Railway generates the admin password, Artalk moderator password and MinIO password automatically.
3. After deploy:
   - Blog: `https://<your-domain>/`
   - Editor: `https://<your-domain>/admin/` — login with `ADMIN_USERNAME` and the `ADMIN_PASSWORD` from the service's **Variables** tab.
   - Comments admin: `https://<your-domain>/comment/sidebar/` — login with `ARTALK_ADMIN_EMAIL` / `ARTALK_ADMIN_PASSWORD`.
   - MinIO console: `https://<your-domain>/minio-console/` — `MINIO_ROOT_USER` / `MINIO_ROOT_PASSWORD`.
   - Terminal: `https://<your-domain>/terminal/`
4. Create your first post in the editor, wait ~60 seconds, and it's live.

## Environment

All variables are optional — one-click deploy works with zero input.

| Variable | Default | Purpose |
|---|---|---|
| `ADMIN_USERNAME` | `admin` | hexo-admin login name |
| `ADMIN_PASSWORD` | `${{secret(16)}}` | hexo-admin login password (auto-generated) |
| `ARTALK_SITE_DEFAULT` | `My Hexo Blog` | Comment system site name |
| `ARTALK_DB_TYPE` | `sqlite` | `sqlite` (volume) or `pgsql`/`mysql`/`mssql` |
| `DATABASE_URL` | — | Connection string when `ARTALK_DB_TYPE` is not sqlite |
| `ARTALK_ADMIN_EMAIL` | `admin@example.com` | First comment moderator email |
| `ARTALK_ADMIN_PASSWORD` | `${{secret(16)}}` | Comment moderator password (auto-generated) |
| `ARTALK_TRUSTED_DOMAINS` | — | Extra origins allowed to call the comment API |
| `ARTALK_LOCALE` / `ARTALK_TIMEZONE` | `en` / `UTC` | Comment UI language / timezone |
| `MINIO_ROOT_USER` | `minioadmin` | MinIO S3 root user |
| `MINIO_ROOT_PASSWORD` | `${{secret(16)}}` | MinIO S3 root password (auto-generated) |
| `TZ` | `UTC` | Container / Hexo / Artalk timezone |

## Prerequisites

- A Railway account with the free Hobby plan or above.
- No Docker, no domain, no database setup required. Volumes and secrets are provisioned by the template.
- (Optional) For PostgreSQL-backed comments: a `DATABASE_URL` — Railway can provision Postgres inside the same project.

## Architecture

```
                ┌─────────────────────────── Railway project ───────────────────────────┐
                │  Service: blog  (one container, one public URL, ~1.5GB peak RAM)      │
                │                                                                       │
 https://site/  │  nginx :80 ── router ─────────────────────────────────────────────┐   │
                │   │  /          → static blog        (serves /app/public volume)  │   │
                │   │  /admin/    → hexo-admin         (hexo server :4000)          │   │
                │   │  /comment/  → Artalk comments    (:23366, SQLite on volume)   │   │
                │   │  /minio/    → MinIO S3 API       (:9000, path-style)          │   │
                │   │  /terminal/ → ttyd shell         (:7681, WebSocket)           │   │
                │   │                                                                   │
                │   │  Volumes: /app/source (posts) · /app/public (site) · /data (DB)   │
                │   └───────────────────────────────────────────────────────────────────┘
                │                                                                       │
                │  supervisord supervises: nginx · hexo server (-s) · regenerate loop · │
                │  artalk · ttyd · minio                                                │
                └───────────────────────────────────────────────────────────────────────┘
```

Notes:
- A `regenerate` supervisor job runs `hexo generate` every 60 seconds, so editor saves go live automatically (Railway volumes don't emit file-watch events, so hexo's watcher can't be relied on).
- Railway limits a service to one public domain; every component is routed under subpaths of that single domain by nginx.

## Deploy

- **One click:** use the Deploy to Railway button. Fill in nothing — every variable has a working default.
- **Post-deploy checks:** confirm `/` returns your blog, `/admin/` shows the login, `/comment/` answers, and `/minio-console/` loads.
- **Scale:** raise the service's memory limit if you store a lot in MinIO.
- **Custom domain:** attach it in the Railway dashboard; nginx listens on port 80.

## FAQ

**How do I publish a post?**
Create/edit it at `/admin/`. The 60-second regenerate loop makes it live automatically; you can also run `hexo generate` in `/terminal/` for instant publish.

**Where are my posts stored?**
`source/_posts/` on the `/app/source` volume — survives restarts, redeploys and even template re-deploys.

**How do I upload images to a post?**
Two options: use the editor's file upload (stored in `source/_uploads`, served under `/uploads/`), or drop files into MinIO (`/minio/`) and reference them as `https://<domain>/minio/<bucket>/<key>`.

**Is the terminal safe?**
It runs an unauthenticated shell in the container. Keep the URL private, or add IP allowlisting in `nginx.conf` if your blog is public.

**Can I use Postgres for comments?**
Yes: set `ARTALK_DB_TYPE=pgsql` and `DATABASE_URL=postgres://...` (e.g. a Railway Postgres service). Default is SQLite on the volume for zero-dependency installs.

**How do I customize the theme?**
The default Landscape theme ships via npm. Fork the repo and replace `hexo-theme-landscape` in `package.json`, or add your own theme under `themes/`.

**Why Railway instead of GitHub Pages / Cloudflare Pages?**
You get a full publishing workflow — browser editor, moderated comments, S3 media storage, terminal access and durable volumes — not just static file hosting.
